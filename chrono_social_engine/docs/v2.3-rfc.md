## 背景

v2.1 完成了因果方向修正（時間 → 關係 → 分析系統 → 沉默 → 語言）。
v2.2 完成了 Behavior Bias Layer（reaction_bias / expression_mode）。

v2.3 的目標不是新增功能，而是讓系統「看見自己在做什麼」。

驗收標準：
> 任何一次異常回應，都能在 30 秒內從 log 找到原因。

---

## 核心架構界線

```
Engine
├─ BehaviorProfile
│ ↓
│ Prompt（LLM 看這層，乾淨）
│ └─ DecisionTrace
↓
Log（調校用，不進 Prompt）
```

**DecisionTrace 絕對不進 LLM Prompt。**
避免模型開始解釋自己的推理、引用系統原因、變得 meta。

---

## 資料結構

```python
@dataclass
class TriggerRecord:
    name:          str
    score:         float
    accepted:      bool
    reason:        str = ""
    priority_rank: int = 0   # 1=主導，數字越大越次要

@dataclass
class DecisionTrace:
    # Bias 決策
    dominant_signal:     str
    candidate_biases:    list[tuple[str, float]]
    selected_bias:       str
    selection_reason:    str
    decision_confidence: float   # 0.91=明確 0.54=邊界案例

    # Salience 決策
    salience_reason:     str

    # Carryover 決策
    carryover_reason:    str

    # 被壓制的訊號
    suppressed_signals:  list[str]

    # Trigger Timeline
    evaluated_triggers:  list[TriggerRecord]

    # Silence 決策
    silence_candidates:  list[tuple[str, float]]
    silence_selected:    str
    silence_reason:      list[str]
```

```python
# v2.2（太敏感）
```

## 四角色共用策略

DecisionTrace 是 chrono_social_engine 核心層的一部分。
四個角色（Akane / Rem / Aoi / Mahiru）共用同一套 Trace 結構。
各角色只有 threshold 和 profile 不同，Trace 格式完全一致。

---

## 不做的事（明確邊界）

- DecisionTrace 不進 LLM Prompt
- v2.3 不砍任何現有 Diagnostics 訊號
- v2.3 不新增情緒狀態或 temporal feature
- Simulation Runner 在 P2，不是 P0
